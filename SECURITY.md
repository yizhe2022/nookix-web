# Security Policy

## Supported Versions

Only the latest version on the default branch is actively maintained.

| Version | Security updates |
| --- | --- |
| `main` / latest | Supported |
| Historical versions | Not supported |

## Reporting a Vulnerability

Do not disclose security vulnerabilities through public Issues, discussions, or social media.

Please use **Report a vulnerability** in the repository's GitHub **Security Advisories** to submit a private report. If private vulnerability reporting has not yet been enabled for this repository, maintainers should enable it in the repository security settings. Until then, contact a repository maintainer before disclosing vulnerability details publicly.

Include as much of the following as possible:

- The impact and affected components
- Minimal reproduction steps or a proof of concept (PoC)
- Affected versions, environments, or configurations
- Any known mitigations or suggested fixes, if available

We will make a reasonable effort to acknowledge reports, assess impact, and work toward a resolution. Please do not disclose vulnerability details publicly before a fix is available.

## Good-Faith Security Research

Good-faith security research is welcome when it follows these conditions:

- Test only accounts, data, and environments you are authorized to access.
- Do not access, modify, or delete other users' data.
- Do not degrade service availability or perform denial-of-service testing.
- Do not publicly disclose or distribute sensitive information you obtain.
- Use the minimum necessary verification steps and stop further exploitation once the issue is confirmed.
